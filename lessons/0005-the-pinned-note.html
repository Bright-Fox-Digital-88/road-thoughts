The Pinned Note

Why chain-of-thought works — a practical detour built on the frozen past.

The one idea: A single forward pass has a finite amount of internal scratch and a fixed amount of computation. Chain-of-thought breaks that ceiling by emitting an intermediate result as a token — moving it out of the ephemeral internal state and into the durable token stream, where every future step can read it back exactly.

This is the practitioner's payoff from the read-out and the causal mask. It explains why "think step by step" makes models smarter — and it rests entirely on a guarantee you've already met.

Movement I · There is no special "thinking" token
🎭 No Token Has a Type CoT vs output is convention, not mechanism The model never flips a switch between "this token is for thinking" and "this one's for the user." Every token is minted by the identical operation — run the pass, soften the logits, sample. What makes a span "reasoning" versus "answer" is purely content and convention: tags, training, or a harness that hides the reasoning. The "strategy" is learned behaviour expressed through content, not a different machine.
Movement II · The past is frozen — guaranteed, not hoped
🧊 The Frozen Past causal-mask invariance (the basis of the KV cache) Each token's representation depends only on the tokens to its left. Appending a new token happens at the right end. So the prior tokens' entire manifestation stack — every layer, every vector — is bit-for-bit identical whether or not the new token exists. The model doesn't trust this; it's structurally guaranteed. With the KV cache the past isn't even recomputed — it's reused, precisely because recomputing would yield the same numbers.
The whole forward pass is deterministic — same weights, same prior tokens, same result, every time. The only dice roll is the sampling step at the very end. So "would the prior stack come out the same?" — yes, by construction.
Movement III · What the note actually buys
📌 The Pinned Note an emitted intermediate result, made durable A single position's internal scratchpad is finite (fixed width, fixed number of layers) — a hard ceiling on the serial reasoning possible for one prediction. Emitting an intermediate conclusion as a token moves it out of that ephemeral state (which would be discarded) and into the durable token stream — where it survives and the next pass can attend to it. Each emitted token got its own full forward pass; its conclusion is now a fixture later passes build on. That is how the model buys more total computation and an external memory.

It is, exactly, showing your work on paper: you offload intermediate conclusions so you don't have to hold them all in a finite head, and so later steps can reference them precisely.

Movement IV · One direction only
➡️ Forward-Only Influence appending shapes the future, never the past A pinned note can't change how an earlier token thought — but it steers every token that comes after it, because they can all attend back to it. That asymmetry is the whole point: the reasoning helps because you've planted a result the rest of the generation will lean on.
Practitioner takeaways for your agent work:
  • "Think step by step" works because it hands the model a bigger, external scratchpad when its internal one would overflow.
  • Reasoning models emit many tokens on purpose — each is more compute and more persisted memory, not just verbosity.
  • Hidden reasoning still costs tokens — the harness may hide the span from you, but those tokens were generated and attended to all the same.
  • Order matters: a conclusion only helps tokens that come after it. Put the reasoning before the answer, never after.

The gears beneath this lesson

  • No Token Has a Type → CoT and final-answer tokens are generated identically; the difference is content/convention/training.
  • The Frozen Past → causal-mask invariance: appending never alters prior tokens (the same guarantee that makes the KV cache correct); the pass is deterministic but for sampling.
  • The Pinned Note → emitting an intermediate result persists it from the finite internal scratchpad into the durable token stream, buying serial compute + external memory.
  • Forward-Only Influence → an appended token shapes later tokens but never earlier ones.
